# AI 추천 시스템 구조 도식화

> LLM 기본 지식 vs RAG 실제 데이터 - 하이브리드 추천 시스템
>
> 작성일: 2025년 11월 7일

---

## 질문: "지금 @봇 해서 여행을 추천해줬을 때, LLM이 이미 학습한 내용에서 추천하는 건가요?"

### 답변: **아니요! 하이브리드 방식입니다.**

우리 시스템은 **LLM의 기본 지식**과 **RAG 실제 데이터**를 **함께** 사용합니다.

---

## 상세 데이터 흐름

```
┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃                  recommend_similar_trips (RAG) 상세 흐름                      ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛

사용자 메시지: "@봇 제주도 자연 경관 좋은 여행지 추천해줘"
                                │
                                ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ STEP 1: Agent가 recommend_similar_trips 도구 선택                             │
│ ──────────────────────────────────────────────                               │
│                                                                               │
│ GPT-4 Turbo가 판단:                                                           │
│ "사용자가 여행 코스 추천을 원함"                                              │
│ "현재 플래너는 제주도 여행"                                                   │
│ "recommend_similar_trips('제주도 자연 경관', limit=5) 호출"                   │
└──────────────────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ STEP 2: 현재 플래너 정보 로드 (Django ORM)                                    │
│ ───────────────────────────────────────────                                   │
│                                                                               │
│ trip = TripPlan.objects.get(trip_idx=trip_id)                                 │
│                                                                               │
│ 추출한 정보:                                                                   │
│ - country_code: 82 (대한민국)                                                 │
│ - region1_idx: 5 (제주특별자치도)                                             │
│                                                                               │
│ → 이 정보를 RAG 검색 필터로 사용!                                             │
└──────────────────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ STEP 3: RAG 검색 (apps/ai/rag.py)                                             │
│ ──────────────────────────────                                                │
│                                                                               │
│ rag = get_rag()                                                               │
│ results = rag.search_similar_trips(                                           │
│     query="제주도 자연 경관",                                                  │
│     country_code=82,                                                          │
│     region1_idx=5,                                                            │
│     limit=5                                                                   │
│ )                                                                             │
│                                                                               │
│ 내부 동작:                                                                     │
│ ┌─────────────────────────────────────────────────────────────────────┐      │
│ │ 3-1. 쿼리 텍스트 → 벡터 변환 (OpenAI Embeddings)                    │      │
│ │      query_embedding = openai.embeddings.create(                    │      │
│ │          model="text-embedding-ada-002",                            │      │
│ │          input="제주도 자연 경관"                                     │      │
│ │      )                                                               │      │
│ │      → [0.0345, -0.0234, 0.0678, ..., 0.0123]  (1536 floats)       │      │
│ └─────────────────────────────────────────────────────────────────────┘      │
│                                                                               │
│ ┌─────────────────────────────────────────────────────────────────────┐      │
│ │ 3-2. pgvector 유사도 검색 (PostgreSQL)                              │      │
│ │                                                                      │      │
│ │      SET ivfflat.probes = 10;  -- 검색 품질 설정                    │      │
│ │                                                                      │      │
│ │      SELECT                                                          │      │
│ │          video_id,                                                   │      │
│ │          title,                                                      │      │
│ │          channel,                                                    │      │
│ │          country_name,                                               │      │
│ │          views_num,                                                  │      │
│ │          metadata,                                                   │      │
│ │          content_embedding <=> '[0.0345, ...]' AS distance           │      │
│ │      FROM trip_course_embeddings                                     │      │
│ │      WHERE                                                           │      │
│ │          country_code = 82           -- 필터 1: 대한민국             │      │
```

## 요약

### ✅ 현재 구조: **하이브리드 방식**

1. **LLM 기본 지식 (GPT-4 학습 데이터)**
   - 일반적인 여행 정보
   - 빠른 응답
   - 비용 없음
   - 하지만 구체적인 일정 제공 어려움

2. **RAG 실제 데이터 (우리가 수집한 YouTube 브이로그)** ⭐
   - 실제 검증된 여행 코스
   - 구체적인 일정 (Day 1, 2, 3...)
   - 조회수 기반 인기도
   - 영상 링크 제공
   - 유사도 기반 정확한 추천

3. **Agent가 자동으로 선택**
   - "맛집 추천" → recommend_places (DB + LLM)
   - "여행 코스 추천" → recommend_similar_trips (RAG)
   - "근처 카페" → search_nearby (Google API)
