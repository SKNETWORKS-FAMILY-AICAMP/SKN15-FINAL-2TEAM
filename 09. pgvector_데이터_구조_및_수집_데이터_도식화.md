## 개요

Triplan의 RAG 시스템은 **PostgreSQL + pgvector** 확장을 사용하여
여행 블로그/영상 데이터를 벡터화하여 저장하고 검색합니다.

### 핵심 특징

| 항목 | 값 | 설명 |
|------|-----|------|
| **테이블명** | `trip_course_embeddings` | 여행 코스 임베딩 저장 |
| **Primary Key** | `id` (bigint) | Auto increment |
| **Unique Key** | `video_id` (varchar) | YouTube 영상 ID 또는 블로그 ID |
| **벡터 필드** | `content_embedding` | 1536차원 벡터 (VectorField) |
| **메타데이터** | `metadata` (JSONB) | 일정, 설명 등 원본 데이터 |
| **Foreign Keys** | `country_code`, `region1_idx`, `region2_idx` | 지역 테이블 참조 |

## pgvector 테이블 구조

### 전체 스키마 (16개 컬럼)

```sql
CREATE TABLE trip_course_embeddings (
    -- Primary Key
    id                  BIGINT PRIMARY KEY AUTO_INCREMENT,
    video_id            VARCHAR(50) UNIQUE NOT NULL,

    -- Basic Metadata (기본 정보)
    title               TEXT NOT NULL,
    channel             VARCHAR(255),
    url                 TEXT,

    -- Location Info (지역 정보)
    country_name        VARCHAR(100),              -- Denormalized (검색 최적화)
    country_code        INTEGER,                   -- FK → countries
    region1_idx         INTEGER,                   -- FK → region1 (도/시)
    region2_idx         INTEGER,                   -- FK → region2 (구/군)

    -- Upload Info (업로드 정보)
    upload_year         INTEGER,
    upload_month        INTEGER,
    views_num           INTEGER,

    -- Vector Embedding (벡터 임베딩) - 핵심!
    content_embedding   VECTOR(1536),              -- 1536-dimensional vector

    -- Metadata (메타데이터)
    metadata            JSONB,                     -- 원본 데이터 (일정, 설명 등)

    -- System Fields (시스템 필드)
    created_at          TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at          TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

## 벡터(Vector) 내부 구조

### VECTOR(1536) 타입 상세

```
┌─────────────────────────────────────────────────────────────┐
│               content_embedding: VECTOR(1536)               │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│ 데이터 구조: float32 배열 (1536개의 부동소수점 숫자)        │
│                                                              │
│ [                                                            │
│   0.0234,      ← 차원 1                                     │
│   -0.1456,     ← 차원 2                                     │
│   0.0789,      ← 차원 3                                     │
│   0.2345,      ← 차원 4                                     │
│   -0.0567,     ← 차원 5                                     │
│   ...          ← 중간 생략 (1531개)                         │
│   0.0321       ← 차원 1536                                  │
│ ]                                                            │
│                                                              │
│ 메모리 크기:                                                 │
│   1536 dimensions × 4 bytes (float32) = 6,144 bytes         │
│                                         ≈ 6 KB per vector    │
│                                                              │
│ 값 범위:                                                     │
│   -1.0 ~ 1.0 (L2 정규화됨)                                  │
│                                                              │
│ 특성:                                                        │
│   - L2 Norm = 1 (단위 벡터)                                 │
│   - 코사인 유사도 계산 최적화                                │
│   - 의미론적 유사성 표현                                     │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

---

### 벡터 시각화 (개념적)

```
1536차원 공간 (개념적 표현, 실제로는 1536차원)

차원 1 (제주도 관련성)
  ↑
  │     ● "제주도 2박 3일" [0.12, -0.34, 0.56, ..., 0.78]
  │    /  \
  │   /    \
  │  /      \
  │ ● "제주 동부" [0.14, -0.32, 0.58, ..., 0.76]
  │              \
  │               \
  │                ● "제주 맛집" [0.10, -0.30, 0.52, ..., 0.74]
  │
  │        ● "서울 관광" [0.05, 0.20, -0.40, ..., 0.30]
  │
  └────────────────────────────────────────→ 차원 2 (여행 스타일)

유사한 여행 코스 = 벡터 공간에서 가까운 위치
코사인 유사도 = 두 벡터 간의 각도 (각도 작을수록 유사)
```

---

### 벡터 연산 예시

```python
# 두 벡터의 코사인 유사도 계산

# 벡터 A: "제주도 2박 3일 자연 여행"
vector_a = [0.12, -0.34, 0.56, ..., 0.78]  # 1536개

# 벡터 B: "제주 동부 일주 코스"
vector_b = [0.14, -0.32, 0.58, ..., 0.76]  # 1536개

# 내적 (Dot Product)
dot_product = sum(a * b for a, b in zip(vector_a, vector_b))
# → 0.95

# L2 Norm (이미 1로 정규화됨)
norm_a = 1.0
norm_b = 1.0

# 코사인 유사도
cosine_similarity = dot_product / (norm_a * norm_b)
# → 0.95 (95% 유사)

# 코사인 거리 (pgvector가 사용)
cosine_distance = 1 - cosine_similarity
# → 0.05 (거리 작음 = 유사함)
```

### JSONB vs TEXT 비교

| 항목 | TEXT (일반 문자열) | JSONB | Triplan 선택 |
|------|-------------------|-------|-------------|
| **저장 형식** | 문자열 그대로 | 바이너리 JSON | ✅ JSONB |
| **쿼리 성능** | 느림 (LIKE 검색) | 빠름 (인덱스 가능) | ✅ JSONB |
| **필드 접근** | 불가능 | `metadata->>'key'` | ✅ JSONB |
| **저장 공간** | 적음 | 약간 많음 | ✅ JSONB |
| **유연성** | 낮음 | 높음 | ✅ JSONB |

**JSONB 쿼리 예시:**
```sql
-- 특정 태그를 가진 여행 찾기
SELECT * FROM trip_course_embeddings
WHERE metadata @> '{"tags": ["제주도"]}';

-- 예산 필터링
SELECT * FROM trip_course_embeddings
WHERE (metadata->>'total_budget_krw')::INTEGER <= 200000;

-- 일정 수 필터링
SELECT * FROM trip_course_embeddings
WHERE (metadata->>'duration_days')::INTEGER = 3;
```

## 인덱스 전략

### 7개의 인덱스

```sql
-- 1. Primary Key 인덱스 (자동 생성)
CREATE UNIQUE INDEX trip_course_embeddings_pkey
ON trip_course_embeddings (id);

-- 2. Unique 인덱스 (video_id)
CREATE UNIQUE INDEX trip_course_embeddings_video_id_key
ON trip_course_embeddings (video_id);

-- 3. 지역 복합 인덱스 (가장 많이 사용)
CREATE INDEX idx_location
ON trip_course_embeddings (country_code, region1_idx);

-- 4. 업로드 날짜 복합 인덱스
CREATE INDEX idx_upload_date
ON trip_course_embeddings (upload_year, upload_month);

-- 5. 조회수 인덱스 (인기 영상 필터)
CREATE INDEX idx_views
ON trip_course_embeddings (views_num DESC);

-- 6. 생성일 인덱스 (최신 데이터)
CREATE INDEX idx_created_at
ON trip_course_embeddings (created_at DESC);

-- 7. 🚀 IVFFlat 벡터 인덱스 (가장 중요!)
CREATE INDEX idx_content_embedding
ON trip_course_embeddings
USING ivfflat (content_embedding vector_cosine_ops)
WITH (lists = 100);
```

```
IVFFlat (Inverted File with Flat Compression)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

작동 원리:
1. 벡터 공간을 100개의 클러스터로 분할
2. 각 벡터를 가장 가까운 클러스터에 할당
3. 검색 시 쿼리와 가까운 10개 클러스터만 탐색

┌─────────────────────────────────────────┐
│        Vector Space (1536차원)          │
├─────────────────────────────────────────┤
│                                          │
│  [Cluster 1]    [Cluster 2]             │
│  100개 벡터     95개 벡터                │
│  ● ● ● ●        ● ● ● ●                 │
│  ● ● ● ●        ● ● ● ●                 │
│                                          │
│       [Cluster 3]     [Cluster 4]       │
│       102개 벡터      98개 벡터          │
│       ● ● ● ●         ● ● ● ●           │
│       ● ● ● ●         ● ● ● ●           │
│                                          │
│  ... (총 100개 클러스터)                 │
│                                          │
│  쿼리 ★ → 가장 가까운 10개 클러스터      │
│          → 약 1,000개 벡터만 검색        │
│          (전체 10,000개 중 10%)          │
└─────────────────────────────────────────┘

성능:
- Full Scan: 5,000ms (10,000개 모두 비교)
- IVFFlat: 13ms (1,000개만 비교)
- 속도 향상: 385배
- 정확도: 98% (Approximate Search)
```

### 인덱스 사용 쿼리 패턴

```sql
-- 1. 지역별 검색 (idx_location 사용)
SELECT * FROM trip_course_embeddings
WHERE country_code = 82
  AND region1_idx = 5
ORDER BY views_num DESC
LIMIT 10;

-- 2. 최신 영상 (idx_created_at 사용)
SELECT * FROM trip_course_embeddings
WHERE upload_year = 2024
  AND upload_month = 11
ORDER BY created_at DESC
LIMIT 10;

-- 3. 인기 영상 (idx_views 사용)
SELECT * FROM trip_course_embeddings
WHERE country_code = 82
ORDER BY views_num DESC
LIMIT 10;

-- 4. 벡터 유사도 검색 (idx_content_embedding 사용)
SELECT *,
       content_embedding <=> '[0.12, -0.34, ...]'::vector AS distance
FROM trip_course_embeddings
WHERE country_code = 82
  AND region1_idx = 5
ORDER BY content_embedding <=> '[0.12, -0.34, ...]'::vector
LIMIT 5;
```

```python
def extract_location(text: str) -> dict:
    """
    텍스트에서 지역 정보 추출 (NER + 키워드 매칭)
    """

    # 국가 키워드
    countries = {
        "대한민국": ["한국", "대한민국", "korea"],
        "일본": ["일본", "japan", "도쿄", "오사카"],
        "태국": ["태국", "thailand", "방콕", "푸켓"],
        "프랑스": ["프랑스", "france", "파리"],
        # ... 더 많은 국가
    }

    # 지역 키워드 (대한민국 기준)
    regions = {
        "서울": ["서울", "seoul", "강남", "홍대"],
        "제주도": ["제주", "jeju", "성산", "협재"],
        "부산": ["부산", "busan", "해운대", "광안리"],
        "경주": ["경주", "gyeongju", "불국사", "첨성대"],
        # ... 더 많은 지역
    }

    # 텍스트에서 매칭
    detected_country = None
    detected_region = None

    for country, keywords in countries.items():
        if any(kw in text.lower() for kw in keywords):
            detected_country = country
            break

    for region, keywords in regions.items():
        if any(kw in text.lower() for kw in keywords):
            detected_region = region
            break

    return {
        "country": detected_country or "대한민국",  # 기본값
        "region1": detected_region,
        "region2": None  # 추가 파싱 필요
    }
```

### 일정(Schedule) 파싱

```python
import re

def parse_schedule(description: str) -> list:
    """
    설명에서 여행 일정 파싱
    """

    schedules = []

    # 패턴 1: "Day 1:", "Day 2:" 등
    day_pattern = r'Day\s*(\d+)\s*[:\-](.+?)(?=Day\s*\d+|$)'
    matches = re.finditer(day_pattern, description, re.IGNORECASE | re.DOTALL)

    for match in matches:
        day_no = int(match.group(1))
        day_content = match.group(2).strip()

        # 장소 추출 (쉼표, 화살표, 줄바꿈으로 구분)
        places = re.split(r'[,\→\n]', day_content)
        places = [p.strip() for p in places if p.strip()]
        places = [p for p in places if len(p) > 2 and len(p) < 50]

        schedules.append({
            "day": day_no,
            "places": places[:10],  # 최대 10개
            "activities": extract_activities(day_content)
        })

    # 패턴 2: "첫째 날:", "둘째 날:" 등 (한글)
    if not schedules:
        korean_day_pattern = r'(첫째|둘째|셋째|넷째|다섯째)\s*날\s*[:\-](.+?)(?=(첫째|둘째|셋째|넷째|다섯째)\s*날|$)'
        korean_days = {"첫째": 1, "둘째": 2, "셋째": 3, "넷째": 4, "다섯째": 5}

        matches = re.finditer(korean_day_pattern, description, re.DOTALL)

        for match in matches:
            day_korean = match.group(1)
            day_no = korean_days[day_korean]
            day_content = match.group(2).strip()

            places = re.split(r'[,\→\n]', day_content)
            places = [p.strip() for p in places if p.strip() and len(p) > 2]

            schedules.append({
                "day": day_no,
                "places": places[:10],
                "activities": extract_activities(day_content)
            })

    return sorted(schedules, key=lambda x: x['day'])
```

### 배치 처리 코드

```python
from apps.ai.models import TripCourseEmbedding
from apps.ai.rag import TripRAG
import logging

logger = logging.getLogger(__name__)

def bulk_create_embeddings(trip_courses: list, batch_size: int = 100):
    """
    대량의 여행 코스를 배치로 임베딩 생성 및 DB 저장
    """
    rag = TripRAG()
    total = len(trip_courses)

    for i in range(0, total, batch_size):
        batch = trip_courses[i:i+batch_size]
        batch_num = i // batch_size + 1

        logger.info(f"Processing batch {batch_num}/{(total + batch_size - 1) // batch_size}")

        try:
            # 1. 임베딩 텍스트 생성
            texts = [course['embedding_text'] for course in batch]

            # 2. 배치 임베딩 생성 (OpenAI API)
            embeddings = create_batch_embeddings(texts, batch_size=batch_size)

            # 3. DB 객체 생성
            objects = []
            for j, course in enumerate(batch):
                obj = TripCourseEmbedding(
                    video_id=course['video_id'],
                    title=course['title'],
                    channel=course['channel'],
                    url=course['url'],
                    country_name=course['country_name'],
                    country_code_id=course['country_code'],
                    region1_idx_id=course['region1_idx'],
                    upload_year=course['upload_year'],
                    upload_month=course['upload_month'],
                    views_num=course['views_num'],
                    content_embedding=embeddings[j],
                    metadata=course['metadata']
                )
                objects.append(obj)

            # 4. Bulk Insert
            TripCourseEmbedding.objects.bulk_create(
                objects,
                batch_size=batch_size,
                ignore_conflicts=True  # 중복 시 무시
            )

            logger.info(f"✅ Inserted {len(objects)} embeddings (batch {batch_num})")

        except Exception as e:
            logger.error(f"❌ Batch {batch_num} failed: {e}")
            # 개별 처리로 재시도
            for course in batch:
                try:
                    save_single_embedding(course)
                except Exception as inner_e:
                    logger.error(f"Failed to save {course['video_id']}: {inner_e}")

# 사용 예시
trip_courses = load_preprocessed_data()  # 10,000개
bulk_create_embeddings(trip_courses, batch_size=100)
```
