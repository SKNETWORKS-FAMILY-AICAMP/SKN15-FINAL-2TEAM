## pgvector란?

```
┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃                              pgvector 개요                                    ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛

pgvector는 PostgreSQL의 확장(extension)으로,
벡터(vector) 데이터 타입과 유사도 검색 기능을 제공합니다.

주요 기능:
├─ Vector 데이터 타입 제공
├─ 유사도 검색 연산자 (<->, <#>, <=>)
├─ 인덱싱 지원 (IVFFlat, HNSW)
└─ 대규모 벡터 데이터 효율적 처리

사용 목적:
- 시맨틱 검색 (Semantic Search)
- 추천 시스템 (Recommendation)
- 이미지/텍스트 유사도 검색
- RAG (Retrieval-Augmented Generation)
```

## Vector 필드 내부 구조

```
┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃                   content_embedding: VECTOR(1536) 상세 구조                   ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛

1. 데이터 타입: VECTOR(1536)
   - pgvector 확장에서 제공하는 커스텀 타입
   - 1536개의 float32 값으로 구성된 배열

2. 메모리 레이아웃:
┌──────────────────────────────────────────────────────────────────────────────┐
│                                                                               │
│  Byte Offset    Value (float32)          Hex Representation                  │
│  ────────────────────────────────────────────────────────────────────────── │
│  0x0000         0.0234                   3D BF 9A 9E                          │
│  0x0004        -0.0456                   BD 3A E1 48                          │
│  0x0008         0.0789                   3D A1 8F 5C                          │
│  0x000C         0.0123                   3C 48 E8 A7                          │
│  ...                                                                          │
│  0x17FC         0.0123                   3C 48 E8 A7   ← Index 1535 (마지막)  │
│                                                                               │
│  Total Size: 1536 × 4 bytes = 6,144 bytes (6 KB)                             │
└──────────────────────────────────────────────────────────────────────────────┘

3. Vector 값 구조 (논리적):
┌──────────────────────────────────────────────────────────────────────────────┐
│  content_embedding = [                                                        │
│      0.0234,    ← Index   0  (차원 1)                                        │
│     -0.0456,    ← Index   1  (차원 2)                                        │
│      0.0789,    ← Index   2  (차원 3)                                        │
│      0.0012,    ← Index   3  (차원 4)                                        │
│     -0.0345,    ← Index   4  (차원 5)                                        │
│      ...                                                                      │
│      0.0678,    ← Index 767  (차원 768)  - 중간지점                          │
│      ...                                                                      │
│      0.0123     ← Index 1535 (차원 1536) - 마지막                            │
│  ]                                                                            │
│                                                                               │
│  각 값의 범위: 일반적으로 -1.0 ~ 1.0                                          │
│  정규화: L2 norm = 1.0 (OpenAI Ada-002는 자동 정규화)                        │
└──────────────────────────────────────────────────────────────────────────────┘

4. Vector 정규화 검증:
┌──────────────────────────────────────────────────────────────────────────────┐
│  L2 Norm 계산:                                                                │
│                                                                               │
│  norm = sqrt(sum(x_i^2 for i in range(1536)))                                │
│                                                                               │
│  예시:                                                                        │
│  norm = sqrt(0.0234^2 + (-0.0456)^2 + 0.0789^2 + ... + 0.0123^2)            │
│       ≈ 1.0000 (정규화된 벡터)                                               │
│                                                                               │
│  정규화되지 않은 벡터는 다음과 같이 정규화:                                   │
│  normalized_vector = vector / norm                                            │
└──────────────────────────────────────────────────────────────────────────────┘

5. Vector 저장 방식 (PostgreSQL 내부):
┌──────────────────────────────────────────────────────────────────────────────┐
│                                                                               │
│  TOAST (The Oversized-Attribute Storage Technique):                          │
│                                                                               │
│  Vector가 6KB이므로 PostgreSQL의 TOAST 메커니즘 적용 가능                     │
│                                                                               │
│  ┌─────────────────────────────────────────────────────────────────────┐     │
│  │  Row 헤더 (24 bytes)                                                │     │
│  ├─────────────────────────────────────────────────────────────────────┤     │
│  │  일반 컬럼들 (id, video_id, title, ...)                             │     │
│  ├─────────────────────────────────────────────────────────────────────┤     │
│  │  content_embedding:                                                 │     │
│  │    - 작은 경우 (< 2KB): Inline 저장                                 │     │
│  │    - 큰 경우 (> 2KB): TOAST 테이블에 저장, 포인터만 유지            │     │
│  ├─────────────────────────────────────────────────────────────────────┤     │
│  │  metadata (JSONB)                                                   │     │
│  └─────────────────────────────────────────────────────────────────────┘     │
│                                                                               │
│  실제로는 6KB 벡터는 TOAST 테이블에 압축되어 저장됨                           │
│  압축률: 약 50-70% (float 데이터는 압축 효율 낮음)                            │
│  실제 디스크 사용량: ~4-5 KB per vector                                       │
└──────────────────────────────────────────────────────────────────────────────┘

6. Vector 비교 연산:
┌──────────────────────────────────────────────────────────────────────────────┐
│  pgvector가 지원하는 유사도 연산자:                                           │
│                                                                               │
│  1. <-> : L2 Distance (Euclidean Distance)                                   │
│     거리 = sqrt(sum((a_i - b_i)^2))                                           │
│                                                                               │
│  2. <#> : Negative Inner Product                                             │
│     -(sum(a_i * b_i))                                                         │
│                                                                               │
│  3. <=> : Cosine Distance                                                    │
│     1 - (sum(a_i * b_i) / (norm(a) * norm(b)))                               │
│                                                                               │
│  우리 프로젝트는 Cosine Distance (<=>)를 주로 사용                            │
│  정규화된 벡터에서는 Inner Product와 Cosine Distance가 동일                   │
└──────────────────────────────────────────────────────────────────────────────┘
```

```
│  │                                                                     │      │
│  │  Step 1: 쿼리 벡터와 100개 클러스터 중심 간 거리 계산              │      │

│  │          ↓                                                          │      │

│                                                                               │
│  성능 비교:                                                                    │
│  ┌────────────────────────────────────────────────────────────────────┐      │
```

## 벡터 검색 쿼리

```
┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃                      실전 벡터 검색 쿼리 예시                                  ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛

사용자 쿼리: "제주도에서 자연 경관 좋고 힐링되는 여행지 추천해줘"

Step 1: 쿼리 텍스트를 벡터로 변환
────────────────────────────────
Python (Django):
  from openai import OpenAI

  client = OpenAI(api_key=settings.OPENAI_API_KEY)

  query_text = "제주도에서 자연 경관 좋고 힐링되는 여행지"

  response = client.embeddings.create(
      model="text-embedding-ada-002",
      input=query_text
  )

  query_embedding = response.data[0].embedding
  # → [0.0345, -0.0234, 0.0678, ..., 0.0123]  (1536 floats)


Step 2: 필터링 조건 준비
───────────────────────
  country_code = 82  # 대한민국
  region1_idx = 5    # 제주특별자치도


Step 3: SQL 쿼리 실행 (Django ORM)
──────────────────────────────────
  from apps.ai.models import TripCourseEmbedding
  from pgvector.django import CosineDistance

  # IVFFlat 파라미터 설정
  with connection.cursor() as cursor:
      cursor.execute('SET ivfflat.probes = 10')

  # 벡터 유사도 검색 + 필터링
  results = TripCourseEmbedding.objects.filter(
      country_code=country_code,
      region1_idx=region1_idx,
      views_num__gte=1000  # 최소 조회수 1,000
  ).annotate(
      distance=CosineDistance('content_embedding', query_embedding)
  ).order_by(
      'distance'
  )[:5]  # Top 5


Step 4: 원시 SQL 버전 (참고)
───────────────────────────
  SET ivfflat.probes = 10;

  SELECT
      video_id,
      title,
      channel,
      views_num,
      metadata->'schedules' AS schedules,
      content_embedding <=> '[0.0345, -0.0234, 0.0678, ...]' AS distance
  FROM trip_course_embeddings
  WHERE
      country_code = 82
      AND region1_idx = 5
      AND views_num >= 1000
  ORDER BY distance
  LIMIT 5;


Step 5: 검색 결과 (예시)
────────────────────────
  결과 1:
  ├─ video_id: "dQw4w9WgXcQ"
  ├─ title: "제주도 2박 3일 완벽 여행 코스 🍊 | 자연 경관 맛집 힐링 여행"

       {"day": 1, "places": ["성산일출봉", "섭지코지", ...]},

  ├─ video_id: "xyz789abc"

  ├─ channel: "제주라이프"
  ├─ views_num: 89,240
  ├─ distance: 0.1567
  └─ ...

  결과 3~5: ...


실행 계획 (EXPLAIN):
────────────────────
  EXPLAIN ANALYZE
  SELECT ...

  결과:
  ┌────────────────────────────────────────────────────────────────────┐
  │ Limit  (cost=10.5..20.3 rows=5)  (actual time=8.2..12.5 rows=5)   │
  │   →  Index Scan using idx_content_embedding                       │
  │      (cost=10.5..1520.3 rows=100)                                 │
  │      (actual time=8.1..12.3 rows=5)                               │
  │        Index Cond: (content_embedding <=> '[...]')                │
  │        Filter: (country_code = 82 AND region1_idx = 5)            │

  │ Execution Time: 12.8 ms  ← 매우 빠름!                             │
  └────────────────────────────────────────────────────────────────────┘


성능 비교:
─────────
  인덱스 없음 (Brute Force):
    - 전체 스캔: 10,000 rows
    - 소요 시간: ~5,000 ms
    - 정확도: 100%

  IVFFlat 인덱스 사용:
    - 스캔: ~1,000 rows (90% 감소)
    - 소요 시간: ~13 ms (380배 빠름!)
    - 정확도: ~98%

  필터링 적용 (country + region):
    - 스캔: ~100 rows (99% 감소)
    - 소요 시간: ~10 ms
    - 정확도: ~98%


최적화 팁:
──────────
1. 먼저 필터링, 그 다음 벡터 검색
   - country_code, region1_idx로 먼저 필터링
   - 필터링된 결과에 대해 벡터 검색
   - 검색 범위 대폭 축소

2. ivfflat.probes 조정
   - probes = 1:  매우 빠름, 정확도 낮음
   - probes = 10: 빠름, 정확도 높음 (권장)
   - probes = 50: 느림, 정확도 매우 높음

3. 결과 캐싱
   - 인기 쿼리는 Redis에 캐싱
   - TTL 1시간 설정

4. 비동기 처리

   - Celery 또는 Django Channels 활용
```
