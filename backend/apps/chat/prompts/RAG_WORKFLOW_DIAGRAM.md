## 🔄 Alternative Flow: 추천만 받기 (auto_add=False)

```
사용자: "서울 맛집 추천만 해줘 (일정에 추가는 안 함)"
  ↓
Agent: recommend_and_add_to_planner(query="서울 맛집", auto_add=False)
  ↓
STEP 1-3: 동일 (플래너 정보 → RAG 검색 → LLM 정제)
  ↓
STEP 4: auto_add=False 체크
  ↓
✨ '서울 맛집' 추천 결과 (추가하지 않음):

**Day 1**:
  • 09:00 - 광장시장 (전통 시장 먹거리 체험)
  • 12:00 - 명동 칼국수 (유명 칼국수 맛집)
  • 15:00 - 북촌한옥마을 (전통 카페 탐방)

**Day 2**:
  • 09:00 - 이태원 맛집거리 (다국적 음식 체험)
  ...

💡 일정에 추가하고 싶으면 auto_add=True로 다시 호출하세요!
```

## 🛡️ Error Handling

### 1. RAG 검색 실패
```
RAG 결과 없음
  ↓
"😅 '서울 맛집'와 관련된 여행 데이터를 찾지 못했습니다. 다른 키워드로 검색해보세요."
```

### 2. LLM JSON 파싱 실패
```
LLM 응답이 JSON 형식이 아님
  ↓
"❌ LLM 응답 파싱 실패. RAG 추천만 제공합니다:
🎯 추천 여행 1: ... (원본 RAG 결과 출력)"
```

### 3. 중복 장소
```
TripItem에 이미 "광장시장" 존재
  ↓
⏭️ Skipping duplicate: 광장시장 (already in Day 1)
  ↓
다음 장소로 진행
```

### 4. Kakao API 실패
```
Kakao API 타임아웃 또는 에러
  ↓
⚠️ Kakao search failed for '광장시장': timeout
  ↓
원본 장소명으로 추가 (주소/좌표 없이)
```

### 5. Day 번호 초과
```
LLM이 day_4 반환 (현재 플래너는 3일)
  ↓
⚠️ Day 4 exceeds total days (3), skipping
  ↓
해당 Day는 건너뛰고 계속 진행
```

## 📊 Performance Metrics

```
전체 처리 시간: 약 5-10초
  ├─ RAG 검색: 1-2초 (pgvector 쿼리)
  ├─ LLM 정제: 3-5초 (GPT-4 호출)
  ├─ Kakao API 검증: 0.5초 × N개 장소
  └─ DB 저장: 0.1초 × N개 장소

메모리 사용량: 약 50-100MB (LLM 응답 캐싱)
```

## 🎯 Key Design Decisions

1. **RAG 우선**: 실제 여행 데이터를 우선적으로 활용
2. **LLM 정제**: RAG 결과를 그대로 사용하지 않고 현재 플래너에 맞게 최적화
3. **중복 확인**: 같은 장소를 여러 번 추가하지 않도록 방지
4. **Kakao 검증**: 장소명의 정확성 확보 및 주소/좌표 자동 추가
5. **유연한 옵션**: auto_add로 추천만 받을지, 자동 추가할지 선택 가능
6. **상세 로깅**: 디버깅 및 모니터링을 위한 로그 강화
